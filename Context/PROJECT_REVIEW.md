# Project review — 5 September 2026

The project has a useful separation between the shared engine, Streamlit UI, and CLI.
Parameterized SQL, typed AI responses, transactional status history, isolated tests,
and consent before web generation provide a solid foundation for a personal workspace.
SQLite is the default storage engine; setting `DATABASE_URL` selects Postgres.

## Fixes implemented

| Problem | Result |
|---|---|
| Saving and exporting cover letters removed blank lines and collapsed DOCX paragraphs. | Paragraph boundaries survive saving, reopening, and DOCX export. |
| Database reads, deletion, and statistics could raise raw driver exceptions. | SQLite and Postgres transaction failures become user-facing errors; affected UI sections handle failures. Failed application/event writes still roll back together. |
| Invalid URL syntax and non-UTF-8 job/legacy files could crash workflows. | These inputs produce handled errors; failed legacy import can be retried after fixing the file. |
| Clearing the browser API-key input retained the previous credential. | Clearing the field removes the session credential; whitespace-only environment keys are treated as absent. |
| Saving in one view left other views and dashboard counts stale. | Saves trigger a refresh; widgets reconcile changed database values while preserving unsaved edits during unrelated reruns. |
| CSV export silently stopped at 500 UI rows or 2,000 core rows. | Exports include every matching record; the UI explicitly identifies its 500-row display limit. Ordering is stable for equal timestamps. |
| Formula-like CSV values could bypass protection using leading whitespace. | Export neutralizes these prefixes too. |
| CLI resume loading read the entire file before enforcing the upload limit. | Reads stop at the configured limit plus one byte before validation. |
| A new analysis could spend API tokens before discovering an invalid database configuration. | Storage initialization occurs before generation. This does not guarantee a later save will succeed if storage fails during generation. |
| Privacy and CLI messages always described local SQLite storage. | Messages reflect the configured backend; the server warning no longer assumes every headless filesystem is temporary. |
| Streamlit tables mixed numbers and text in one column, and used deprecated sizing arguments. | Detail values are consistently strings and sizing uses `width="stretch"`. |
| Ruff reported 13 baseline issues. | Imports and annotations now satisfy the configured lint rules. |

## Verification

- Baseline: 16 existing tests passed; Ruff reported 13 issues.
- After fixes: 30 unittest tests pass, including four Streamlit AppTest interaction tests.
- Regression coverage includes paragraph preservation, malformed input, database failures,
  rollback, credential clearing, synchronization between views, and complete filtered export
  with 2,002 applications.
- Tests use disposable SQLite databases and mocked AI/Postgres calls. No live OpenAI calls
  or changes to the configured personal/hosted database were made.
- Ruff and `git diff --check` pass.
- The optional pytest runner was unavailable in the active interpreter; verification used
  the repository's supported unittest command.
- DOCX content and paragraph structure were verified by reopening generated bytes. Visual
  rendering was unavailable because LibreOffice and Poppler were not installed.
- Live Postgres behavior, live model output quality, browser appearance, and accessibility
  were not validated by these checks. AppTest exercises Streamlit behavior without a browser.

## Remaining improvement priorities

1. **Recover drafts after a save failure.** Keep a generated bundle in session state when
   persistence fails, with a save retry that does not regenerate or spend more API tokens.
2. **Protect stored work.** Add backup/restore and versioned schema migrations. Tracker CSV
   exports omit generated artifacts and status history, so they are not full backups.
3. **Strengthen concurrency.** Serialize first-use initialization; make bulk status edits
   transactional; use row locking or optimistic version checks for concurrent edits.
4. **Test Postgres in CI.** Use a disposable service to cover schema initialization, pooling,
   CRUD, search, rollback, and event cascades. Dialect and mocked-error tests do not establish
   live backend compatibility.
5. **Handle larger libraries efficiently.** Add pagination and generate CSV on demand from
   tracker columns. Complete exports currently load matching application artifacts in memory.
6. **Keep hosted access personal until isolation exists.** The app has no login or per-user
   ownership checks; visitors share the configured database. Separate API keys do not isolate
   records. Multi-user support needs authentication and authorization across all queries.

These are follow-up architecture/features, not claims that they were implemented in this review.
